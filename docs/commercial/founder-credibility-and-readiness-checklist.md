### 2. Educational LinkedIn Post Template (Task 3 Draft)

**Topic:** The Hidden Mechanics of Meta CAPI Deduplication Failures in Shopify

```text
Why does Meta Ads Manager sometimes report 25% more purchases than Shopify actually recorded?

In our technical work building Commerce Truth Lab, we frequently analyze how browser tracking pixels and server-side Conversions API (CAPI) interact.

Here is the exact technical failure point many scaling Shopify stores face:

When a customer checks out, the browser pixel fires a `Purchase` event with a unique `event_id` token generated by the client JavaScript. Concurrently, the server-side webhook or app fires the same `Purchase` event directly to Meta's Graph API.

Meta uses the `event_name` and `event_id` pair to deduplicate these into a single reported purchase.

However, if:
1. The server payload uses the Shopify order ID (e.g., "1045") while the browser pixel uses an anonymous session token or timestamp,
2. Or the server event fires with a 30-minute delay after the browser event window closes,

Meta cannot match the two events. The algorithm counts BOTH as independent conversions.

Result?
• Artificially inflated conversion counts in Ads Manager.
• Distorted blended ROAS figures.
• Bidding algorithms optimizing against duplicate purchase signals.

We built an open, deterministic audit engine to test for this mathematically using sanitized transaction exports:
https://commerce-truth-lab.vercel.app/demo

How is your team currently verifying that your server CAPI and browser pixel events share matching tokens?
```
