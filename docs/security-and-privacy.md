# Security and Privacy Architecture — Production Milestone 1

Commerce Truth Lab v1 is designed with a defense-in-depth, evidence-first architecture prioritizing **strict tenant isolation**, **zero plaintext customer PII storage**, and **deterministic audit boundaries**.

---

## 1. Zero Plaintext PII Policy (Salted Pseudonymization)

Commerce Truth Lab **never stores customer names, emails, physical addresses, or phone numbers in plaintext**.

### Pseudonymization Mechanism
- When raw CSV exports (such as Shopify order exports) are uploaded, any column designated as a customer identifier (e.g. `customer_email`, `customer_id`, `phone`, `customer_name`) is intercepted during staging and ingestion.
- The raw value is normalized (lowercased, trimmed) and concatenated with a cryptographically secure salt (`PSEUDONYMIZATION_SALT`).
- The value is hashed using SHA-256:
  $$\text{Pseudonym} = \text{"CUST\_"} + \text{SHA-256}(\text{normalized\_value} \parallel \text{salt})[0:16]$$
- Only the pseudonymized identifier (`CUST_<hash>`) is persisted into the database.
- Neither raw email addresses nor customer names are stored in database records, logs, or exported reports.

---

## 2. Multi-Tenant Isolation Model

Tenant isolation prevents one merchant from ever observing, querying, or modifying another merchant’s data.

### Database Scoping
- All primary business entities (`workspaces`, `orders`, `payments`, `courier_settlements`, `refunds`, `purchase_signals`, `findings`, `upload_metadata`, `audit_runs`, `audit_logs`) are partitioned by `workspace_id`.
- Composite primary keys `(workspace_id, id)` ensure data independence and prevent primary key collision across stores.

### Authorization & Boundary Enforcement
- All private workspace endpoints (`/api/workspaces/{workspace_id}/*`) require JWT bearer authentication.
- Access is strictly gated by the `verify_workspace_access` dependency:
  - Verifies that `current_user.id == workspace.owner_id` or that an active row exists in `workspace_members`.
  - Attempts by unauthorized users to read or mutate a foreign workspace return `HTTP 403 Forbidden` (or `HTTP 404 Not Found`).
  - Cross-tenant leakage is prevented at both the application router and query filter levels.

---

## 3. Authentication & Credential Storage

- **Password Hashing:** Passwords are never stored in plaintext. Commerce Truth Lab uses **PBKDF2-HMAC-SHA256** with unique 16-byte random salts and 100,000 iterations.
- **Session Tokens:** Stateless signed JWTs (`HS256`) with strict expiration windows (7-day default, configurable via `JWT_SECRET_KEY`).
- **Timing Attack Mitigation:** Password verification uses constant-time string comparison (`hmac.compare_digest`).

---

## 4. Production Database & Migrations

- **Database Engine:** Dual-driver asynchronous SQLAlchemy 2.0 engine:
  - **Production:** PostgreSQL via `asyncpg` (`postgresql+asyncpg://...`).
  - **Development / CI Fallback:** Async SQLite via `aiosqlite` (`sqlite+aiosqlite://...`).
- **Migration Management:** Schema versioning is managed via **Alembic** (`apps/api/alembic/`), guaranteeing deterministic upgrades and rollbacks across environments.

---

## 5. Audit Logging & Non-Repudiation

- High-impact events are synchronously written to the immutable `audit_logs` table:
  - `workspace_created`
  - `csv_uploaded`
  - `audit_executed`
  - `report_exported`
- Audit logs capture `timestamp` (UTC ISO 8601), `workspace_id`, `user_id`, `action`, and non-PII operational details.

---

## 6. Anti-Hype & Non-Speculative Guardrails

Findings generated by Commerce Truth Lab represent **reconciliation anomalies and missing signals** between provided records. The system adheres to strict communication principles:
- **No false claims of fraud:** A missing settlement or value mismatch is reported as a discrepancy, not confirmed theft.
- **No recovered revenue hype:** CTL does not promise "recovered revenue" or claim credit for funds collected.
- **No causal ROAS assertions:** Ad signal disparities highlight tracking delivery gaps, not marketing efficiency or causal conversions.
- **Explicit evidence completeness:** Incomplete evidence states are flagged explicitly (CTL-009) rather than guessed.
